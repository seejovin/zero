# Android device validation — outstanding

These are release checks to execute on devices. They are not claims of completed testing. Begin with an unfunded, newly created wallet. Never use a valuable production phrase as a test fixture.

## Added 0.12.0 private-engine gates — outstanding on Android

- Build from the exact native/JS/Kotlin source with the pinned tools. Generate both Android ABIs and UniFFI; run all Gradle/JVM suites and lint, include required notices/corresponding source, and sign with the existing certificate. Source metadata and host VM tests are not an APK.
- Verify compiled release gates reject entry before any protocol-key load or network request in the normal unqualified build. A manifest, server response, environment flag or Settings preference must not bypass them.
- In a separately qualified fixture build, exercise real hash-pinned WebView resources, strict CSP, WASM, transferred MessagePorts, blocked navigation/network/file access, no JS interface, no console/debug reporting and stale/cross-session message rejection.
- Validate Keystore journal keys, current-vault journal authentication and per-wallet catalog isolation. A wrong wallet's valid cache/journal must fail closed. Lock/background during initialization/proving/file selection/optional authentication must invalidate obsolete approvals while retaining already-released uncertainty.
- Measure complete initial scan, historical rollover receipts/checkpoints, encrypted chunk commits, one/eleven-input proving, memory pressure and restart on API30/current Android. No unavailable scan may display a complete zero balance. Proving parameters total roughly260MiB uncompressed for the eleven supported shapes; host timing is not device timing.
- Exercise missing/duplicated/out-of-order logs, historical-prefix omissions, rollover-block receipt omissions, final checkpoint mismatch, RPC timeout, corruption and storage-full errors. A rejected scan must heal on a later complete retry without losing pending reservations or advancing an invalid durable cursor.
- Cancel an unreleased intent, create another using the same inputs, then restart. Cleanup of the older cancellation must not clear the newer reservation, including partially overlapping inputs. Cache-write failure must block send readiness.
- Interrupt after approval, proof reservation, envelope commit and first release. Restore local activity and exact bytes after restart, with no automatic broadcast. Lost acknowledgement must reconcile via complete pool scan plus exact calldata/receipt effects; a spent nullifier alone is not a receipt.
- Verify one original provider fee and cumulative native cap across outer reverts/retries. Unknown outcomes cannot create a new nonce. A canonical finalized revert can permit an explicitly requested new outer attempt with the same private proof only under the remaining original cap. Contradictory finalized history must halt processing.
- Export encrypted private history to a selected document and verify exact readback before confirmation. A READY proof exposed through export must remain noncancellable even if the file operation fails. Import with wrong key/wallet/corrupt/truncated bytes must preserve the existing namespace.
- Restore a seed with incomplete/old history: quarantine, durable latest cutoff, wait for finalized cutoff, complete scan, explicit self-sweep fee approval, sequential batches, canonical final receipts and final scan before unlock. Empty scans and fee-insufficient dust cannot silently waive recovery requirements.
- Verify the off-white private Deposit/Send/review/backup/recovery screens at320dp, large fonts, keyboard open and reduced-motion settings. A private `0zk` address must never enter an ordinary public signing/RPC path. No automatic shielding, public fallback or asset migration may occur.
- Before real-value testing, provision reviewed current and historical deployment pins, authenticated shared fee/gateway configuration, independently operated relay and bounded funded treasury. Require explicit sender/recipient/amount authorization for any actual payment; none was performed during implementation.

## General device checks

1. **Package and boot:** verify APK SHA-256/signing certificate; install on API 30 and current Android devices; cold-launch on ARM64 and x86-64. Include a 16 KiB-page ARM64 device. Confirm the installed package is not debuggable and only expected Internet/biometric/overlay permissions are requested.
2. **Onboarding and resume:** create/import with no app PIN and no device screen lock. Creation opens the saved wallet immediately and shows a success dialog with the recovery path and accurate local-custody message. Force-stop/cold-launch and verify the same address and 24 words remain, with no mandatory challenge or replacement wallet. Repeat after upgrading an unfinished v1 wallet, preserving its original device-authentication requirement. Recovery remains concealed until explicitly revealed.
3. **Restore interoperability:** restore an unfunded known phrase and verify the expected first Ethereum address, with the same address on Base. Reject invalid words/checksum and unsupported passphrases without replacing an existing wallet.
4. **Optional app lock:** use Profile → Settings to enable, change and disable a six-digit app PIN. Reject four/eight-digit or nonnumeric input. Verify leading zeroes and failed-PIN backoff across force-stop/reboot. Exercise the biometrics/device-screen-lock mode; the UI must identify its fallback as the existing phone credential. Cancel at each prompt, lock/background during a queued callback, change biometric enrollment and remove/change the device lock. Enabled locks must gate signing/reveal with fresh authorization; Off must not show an app-auth prompt. A biometric callback without the authorized cipher must not decrypt.
5. **Lifecycle, copy and screen privacy:** background, rotate, kill and resume during phrase display, review, authentication, signing, journal commit and RPC submission. Verify screenshots work on the visible recovery-word page and are blocked elsewhere. Verify phrase views blank on background and recent-app thumbnails do not show the words, especially on API 30–32 where only secure-window/lifecycle protection is available. Copy must produce all words in order, hide the system preview via the sensitive flag and attempt to clear its own clipboard entry after 60 seconds without erasing a newer unrelated copy. Test process-death and foreground-clipboard limits; the app cannot guarantee deletion by clipboard managers or photo backup. No phrase may enter saved instance state, logs or app backups. Check overlays/obscured taps and preserve uncertainty for already-transmitted requests.
6. **Live read-only network:** verify mainnet chain IDs; compare ETH/USDC/EURC balances, canonical block hashes, and token contract addresses against independent sources on both networks. Verify stale/malformed/wrong-chain RPC responses and outages preserve last observations and block unsafe sends.
7. **Transaction transport faults:** use an explicitly controlled RPC test harness or proxy without funded keys. Exercise duplicate submit responses, acceptance followed by timeout, disconnected startup with durable signed bytes, wrong returned hash, malformed receipt, missing token Transfer event, replaced nonce, inconsistent finality, and network reorganization. Repeated submission must preserve the same hash and signed bytes.
8. **Base fees:** compare displayed execution limit and L1/operator estimates with independent mainnet observations. Receipt accounting must sum all three fee components. Missing fee evidence must remain unresolved, not become zero. An over-budget actual fee must preserve the true transaction outcome.
9. **Storage and audit:** exercise disk-full/write errors before and after vault rename and signed-journal commit. No bytes may be broadcast before durable signing evidence exists. Export an audit and confirm it omits raw signed transaction bytes and all key/seed material. Confirm journal/account/network mismatches fail closed.
10. **Funded validation:** any real transfer must be separately authorized by its owner with a specific recipient, asset, network, and amount. The build/test workflow does not perform it. Verify native USDC receives, actual fee payment in ETH, confirmed recipient balance, and finalized receipt on each intended network before a broader release.
